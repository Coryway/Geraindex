# skill 13 · 发布前闸门（对外更新榜单之前的最后一步）

> 版本 v1.0 · 2026-11-20 · 依 `_过目/归档/148_skill封装规范` 七段契约
> 依赖：`抓取脚本/_verify_p0_frontend_20261120.py`（交付包对拍）、`skills/00_start/preflight.py`、`抓取脚本/verify_all.js`
> **本 skill 不生产任何数据、不联网、不采集、不改主榜。** 它只回答一句话：**现在能不能对外发。**

---

## 人话版（先读这段）

发榜前跑一条命令，亮三盏灯，全绿才发：

1. **环境灯**（G1）：工具、路径、主榜版本、交付包文件齐不齐 —— 有没有"我以为在跑，其实跑的是旧东西"
2. **主榜灯**（G2）：主榜自己算得对不对（41 项校验）
3. **交付包灯**（G3）：**你手上的主榜** 和 **你准备发出去的那个文件** 是不是同一份数据

第三盏是最容易翻的一盏，因为它查的不是"数字对不对"，而是"**发出去的东西是不是最新的**"。这个项目已经翻过一次：v34 的两个单文件 HTML 打到 11-17 就停在 `v5.41-95`，主榜后来升到 `v5.42-95`、五个展示字段全下线，单文件里却还带着 `rank_display` 95 款、`rank_band` 65 款有值 —— 页面能正常打开、数字看着也对，但**发出去的就是旧包**。这种错靠肉眼看永远发现不了，只有对拍能抓。

**一句话：G3 红 = 不要发，回去重新打包，再跑一遍。**

## 1 什么时候必须跑

| 场景 | 跑不跑 |
|---|---|
| 主榜改动后要发给用户 / 上线 | **必须**，且必须是最后一步 |
| 只改了前端样式、没碰数据 | **必须**（样式也可能顺手改了取数字段） |
| 重新打了单文件包 / ZIP | **必须**（打包最容易带旧数据） |
| 内部预览、给人看个样子 | 可跑 `--allow-stale-html` 临时放行，但**不得对外** |
| 只跑采集、还没算分 | 不用，此时主榜本来就没变 |

**顺序铁律**：`07 改主榜 → export_datajs.js → build_tiers_v3.py → 前端打包 → 13 闸门 → 对外`。13 之前任何一步补跑过，都要重跑 13。

## 2 三道闸的判据

| 闸 | 命令 | 通过判据 | 不通过说明什么 |
|---|---|---|---|
| **G1** preflight | `skills/00_start/preflight.py` | 输出含 `READY` 且无 `NOT READY` | 环境或文件链断了：脚本缺、版本号不一致、采集范围违规 |
| **G2** verify_all | `node 抓取脚本/verify_all.js` | `总计 PASS 41 / FAIL 0` | 主榜自身算错：九档重算、字段同源、前端常数任一不符 |
| **G3** 交付包对拍 | `_verify_p0_frontend_20261120.py` | `counts.data=0`、`counts.code=0`、`counts.html=0` | 发出去的文件与主榜不同源（详见 §3 三类） |

G3 内部再分三类，判定互不掩盖：

1. **data.js**：21 字段 × 116 款与主榜逐字段比（`v_net` / `P` / `U` 拆解 / `correctedPct` / 四轴 / 证据分 / 稳定度 / `rank`）。不一致 = 导出没跑或跑错版本。
2. **单文件 HTML**：从 HTML 里抠内嵌 `window.GUITAR_DATA` 再比一遍；另查 `window.GUITAR_META.version` 是否等于主榜版本，以及五个已下线字段（`rank_display`/`rank_band`/`rank_band_lo`/`rank_band_hi`/`rank_range_T`）是否复活。
3. **源码**：`app.js` / `index.html` 里是否把陈旧副本当**主源**取数、是否 `fetch()` 本地 JSON。

## 3 输入契约

| 输入 | 路径 | 缺了怎么办 |
|---|---|---|
| 主榜 | `MultiBrand_Ranking_Data.json` | G2 直接 FAIL，不进 G3 |
| 前端交付包 | `<项目根>/前端交付包/` 5 文件 | 缺文件 → G3 FAIL 并点名 |
| 单文件交付物 | `_过目/器度_电脑单文件.html`、`器度_手机单文件.html` | 一个都没有 → G3 只报 data.js/源码结论，**并提示"未找到单文件包"** |

## 4 输出契约

| 产物 | 路径 | 说明 |
|---|---|---|
| 终端三灯 + 结论 | stdout | `PASS` / `禁止对外发布` |
| 闸门记录 | `reports/_skill13_<ts>.json` | 每次新建，含三闸 pass 与 detail，不覆盖历史 |
| 抽验明细（G3 生成） | `_过目/11_七项P0数据侧交付_20261120/抽验记录_20261120.md` + `.json` | FAIL 逐条带 uid 与值 |

退出码：**0 = 可发布；2 = 阻断（禁止对外）；3 = 有放行项（仅可内部预览）**。

## 5 参数

| 参数 | 作用 | 红线 |
|---|---|---|
| 无参数 | 三闸全跑 | 对外发布只用这个 |
| `--quick` | 只跑 G3 | 仅在 1、2 刚跑过、且期间没动过脚本时可用 |
| `--allow-stale-html` | 单文件版本落后时放行，返回码 **3（WAIVER）** | **只许内部预览**；对外发布禁止使用。放行不是 PASS：结论仍写"禁止对外发布"，报告里记 `allowStaleHtml: true` |

## 6 失败怎么办（按症状查）

| 症状 | 最可能的根因 | 修法 |
|---|---|---|
| `data.js 与主榜 N 处不一致` | 主榜改了没重导 | 跑 `node 抓取脚本/export_datajs.js` |
| `单文件 HTML N 项不一致` + `版本落后` | 打包用的是旧 `data.js` / 旧 HTML 模板 | 重新打包两个单文件与 ZIP，再跑 13 |
| `下线字段复活：rank_display 有值 95 款` | 包里是 v5.42 之前的数据 | 同上一行；这是"旧包"的指纹 |
| `源码 X 处读陈旧副本` | `FIELD_MAP` 首项写成 `price.netCostCNY` 之类 | 首项必须是 `value.*`，旧字段只能作兜底 |
| `源码含 fetch()` | 违反了"前端禁 fetch 本地 JSON" | 改走 `data.js` 的 `window.GUITAR_DATA` |
| G2 `FAIL 1`（`rank_band`） | 展示字段半下线 | 全下线或全自洽，二者之一 |
| G1 `NOT READY` | 版本号三处不同源 / 采集范围违规 / 关键脚本缺失 | 看 preflight 逐项输出，别猜 |

